Карточка заявки v4 · плоские строки

Рельса 680px, ноль подложек, всё на 1px-разделителях. Порядок: шапка → вопрос клиента → детали заявки (тип, ответственный, тихий inline-edit параметров) → вложения → разбор (таблица всегда, даже для одного объекта) → телеметрия выбранного объекта → оценка разбора → комментарии → связанные заявки → передать монтажникам. Ответ живёт в липком баре снизу: щёлкните поле «Ответить клиенту…» — оно раскроется, появятся шаблон, публичный/приватный и чип «черновик ИИ» для выбранного объекта. Копирование для монтажника переехало из бара в секцию «Передать монтажникам»: два формата — календарь и мессенджер — и текст появляется только по кнопке. Активная секция помечена лаймовой полосой слева. Клик по строке таблицы выбирает объект и обновляет телеметрию; иконка ▤ в строке открывает и закрывает трек-панель. Если тип заявки «Не указан», «Детали заявки» раскрываются сами — чинить нужно там. В баре работают «Шаблон ▾» (инлайн-панель над баром: поиск, категории, плейсхолдеры, предпросмотр; [сегодня]/[вчера]/[завтра] заблокированы — считаются по МСК) и «Ещё ▾» → модалка смены статуса. Смена статуса ВСЕГДА через модалку: там обязательный комментарий, дата возврата и гард по типу заявки. У вложений — плитки файлов с пер-файловым статусом OCR и агрегатный прогресс; ДЕЙСТВИЕ «Продолжить распознавание» живёт в «Разборе» (это тот же прогон, что «Обновить разбор»). Номер и дату в строке разбора правит карандаш — бэкенд пересчитывает телеметрию и вердикт этой строки. У всех кнопок есть подсказки — наведите. Разбор разделён по стоимости: факты и предварительный вердикт считаются правилами бесплатно при открытии заявки, модель зовётся отдельной кнопкой «Ответ ИИ» в телеметрии — ОДИН вызов на всю заявку, уверенность и обоснование приходят по каждому объекту. Источник вердикта виден по пилюле: пунктир — правила, сплошная в цвет вердикта с ✦ — ИИ, нейтральная с ✎ — ручная правка оператора. Переключатель «вердикт» показывает оба состояния. Переключатель «роль» показывает демо-витрину: правки остаются на месте, но погашены и подписаны «Недоступно в демо-режиме», анализ разрешён один раз на заявку. Переключатель «состояния» включает редкие беды по одной: трудные строки разбора (номер не в формате, объект не найден, номер не распознан OCR, спецтехника), агрегатную заявку ОДКР и сорванные запросы. Всё разом не показываем — карточка должна оставаться читаемой. ⤢ в шапке разворачивает карточку на всю ширину, ▤ там же — тот же тумблер трек-панели, что и в строке таблицы. «Подтвердить» в модалке статуса показывает случай, когда Okdesk комментарий принял, а статус оставил прежним.

Заметки для реализации. 1) Все 8 колонок разбора влезают в 648px без скролла за счёт коротких заголовков — полные подписи («ГЛОНАСС заявл.», «По факту») ушли в тултипы. 2) Статус «В работе» приходит цветом #2B6684 — текст им нечитаем, поэтому обводка цветом статуса, а текст осветлён до #7EC8E3; правило «цвет статуса → осветлённый текст» нужно заложить в src/lib/status.ts. 3) Блок «Почему такой вердикт» — это существующий reasoning из TelemetryPanel.tsx, которому раньше не хватало подписи. 4) Гард «Сначала укажите тип заявки» завязан на тип: выберите в «Деталях» тип «Не указан» — предупреждение появится в баре, «Ответить и решить» и «Подтвердить» в модалке заблокируются (Okdesk отклоняет смену статуса при type_code = inner). 5) Статус «В работе» Okdesk открывает только для типов departure / departure_fuel — в меню «Ещё» это написано подписью пункта. 6) Плейсхолдеры шаблонов — русские [квадратные скобки], [сегодня]/[вчера]/[завтра] считаются автоматически по МСК и в форме заблокированы, остальные предзаполняются из разбора выбранного объекта. 7) Пустые «Местоположение техники» / «Контактное лицо» / «Номер телефона» блокируют перевод в «В работе» (баг 64197) — поэтому пустой параметр подсвечен предупреждающим плейсхолдером. 8) Источник вердикта — поле verdict_source: rules (пунктирная пилюля, хвост «по правилам») / ai (сплошная обводка в цвет вердикта, глиф ✦ и полоса доверия из confidence) / operator (нейтральная обводка и глиф ✎, ручная правка сильнее машины). Заливку не трогаем — она занята статусами Okdesk. heuristic_category остаётся в модели после прогона: если он разошёлся с verdict, под таблицей и в телеметрии печатается «правила: X → ИИ: Y». 9) reasoning, confidence и draft_answer приходят только от модели, поэтому до нажатия «Ответ ИИ» этих блоков нет физически — на их месте кнопка. Служебных чисел («~N токенов», «≈N с») на ней НЕТ: такого расчёта в проекте не существует, подпись честная — сколько объектов уйдёт за один вызов и что шаг платный. Кнопка одна на заявку: мультиобъектную ведёт POST /issues/{id}/batch/ai (модель получает факты всех строк разом и отвечает по каждой), одиночную — automate, он богаче (few-shot, проверка возобновления данных, разбор комментариев). Ручные правки оператора прогон не перезаписывает, строки без телеметрии в модель не уходят. 10) Роль demo — только чтение: правки не прячем, а гасим и подписываем «Недоступно в демо-режиме»; один разбор на заявку помечается в localStorage.demo_analyzed_<id>. 11) Авто-дораспознавание больших PDF — цикл проходов с лимитом 15 и остановом, когда ocr_progress.pages_done перестал расти; при остановке кнопка обязана разблокироваться, иначе залипнет навсегда. 12) Раскрытость секций — одна запись localStorage.issueCardSections на все секции; активная секция (лаймовая полоса) считается отдельно и в неё не пишется. 13) Подсветка метрик — HIGHLIGHTED_METRICS в TelemetryPanel.tsx: обводка акцентом и белое значение у метрик, обосновывающих вердикт; у остальных рамка прозрачная, чтобы плитки не «прыгали». 14) Авто-уведомления Okdesk («перешла в статус») ловятся по тексту и красятся нейтрально: это не ответ человека. Регэксп обязан быть по [а-яё] — \w в JS кириллицу не матчит. 15) Прочерк «____» в тексте монтажнику — единственный честный способ показать, что поля в заявке нет: не выдумываем и не молчим. 16) «Статус не изменён — смените вручную в Okdesk» показываем всегда, когда status_changed = false: иначе оператор считает, что заявка ушла из работы. 17) Статус OCR у файла — поле ocr в GET /attachments (done / partial + pages_done / queued / unavailable), данные лежат в кэше ocr:<att_id>. Раньше у любого извлекаемого файла писалось «ИИ читает» — в том числе у PDF, прочитанного на 4 страницы из 6. 18) Дата в строке разбора правится через POST /issues/{id}/batch/date: телеметрия и вердикт строки считаются заново за новую дату (симметрично /batch/plate). 19) Статус и тему связанных заявок бэкенд достаёт из ЛОКАЛЬНОГО кэша заявок — Okdesk в связях отдаёт только id, а отдельный запрос на каждую дочернюю — это N обращений при открытии карточки. Нет в кэше → строка без подписи, но со ссылкой. 20) Ссылка «открыть в Okdesk» — поле okdesk_url: адрес портала знает только бэкенд (OKDESK_BASE_URL, из него отрезается /api/v1). Нет адреса → кнопки нет, вести в никуда нельзя. 21) Регион в подвале выводится из кода в гос.номере — отдельного поля в системе нет. 22) Кто и когда переписал вердикт вручную — verdict_edited_by / verdict_edited_at; при ручной правке обоснование и черновик ИИ снимаются, иначе текст спорит с пилюлей.
